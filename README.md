# gimps-gpu — образ для поиска простых Мерсенна на арендованной GPU (+ CPU)

Образ Docker и скрипты, которые разворачивают на машине с NVIDIA RTX 30/40/50 всё нужное для GIMPS: GPU считает PRP или TF, процессор параллельно делает P-1 в mprime.
Задания получаются и результаты отправляются в PrimeNet автоматически, под вашим логином mersenne.org. Весь ход работы виден в одном живом журнале (`gimps-watch`).

| Компонент | Версия (последние на 28.10.2026) | Что делает |
|---|---|---|
| **PRPLL-NTT** (`prpll-cuda`, `prpll-ocl`) | gwoltman/gpuowl master `7ee576c` (v8.0-514, 26.10.2026) | PRP-тесты на простоту на GPU |
| **mfaktc** | primesearch/mfaktc main `28bb656` (0.24.1 + 129 исправлений, 26.10.2026) | Trial factoring (TF) на GPU |
| **mprime** (Prime95 для Linux) | 30.19 build 20, проверка SHA256 | P-1 / PRP / ECM на CPU |
| **AutoPrimeNet** | 2.0.2 (`b4426a1`, 16.10.2026) | Задания и отчёты PrimeNet для GPU-программ, загрузка PRP-proof |
| **rclone** | 1.75.2 | Внешний бэкап (Google Drive / S3) |
| **CUDA** | 12.9.1 (последняя 12.x) | Сборка и NVRTC |
| `gimps-start` / `gimps-watch` / `gimps-status` / `gimps-stop` / `gimps-backup` | — | Запуск, живой журнал, сводка, остановка, бэкап |

Основные GPU: RTX 30xx (sm_86), RTX 40xx (sm_89), RTX 50xx (sm_120); дополнительно T4, A100, H100, B200, B300.
**Требования к хосту:** драйвер NVIDIA ≥ 575. На vast.ai это фильтр *CUDA ≥ 12.9*.

> Почему не CUDA 13.x: ей нужен драйвер ≥ 580, это отсекло бы часть офферов vast.ai, а mfaktc и PRPLL от неё не ускоряются. Собрать на 13.x можно: Actions → build-image → Run workflow → `cuda_ver`.

- **Новая задача:** что считается, оценка в GHz-days, сколько займёт, скорость и полный снимок GPU (загрузка, температура, вентилятор, мощность/лимит, частоты ядра и памяти, VRAM, P-state, причины снижения частоты) или CPU.
- **Каждый 1 %:** процент, сколько осталось, скорость (GHz-d/day; для PRP ещё мкс/итерацию), краткое состояние GPU.
- **Конец задачи:** результат (составное / делителей нет / ★ найден делитель / ★★★ вероятно простое) и кредит, который засчитал PrimeNet.
- `gimps-watch GPU0`, `gimps-watch CPU`, `gimps-watch M141234567` — только нужные строки; `gimps-watch -n 200` — больше истории. Выход — Ctrl+C, расчёт не останавливается.
- Журнал пишет фоновый `gimps-monitor` в `/data/logs/progress.log`. В режиме Docker ENTRYPOINT он же идёт в `docker logs` (кнопка LOG на vast.ai).

**GHz-days:**
- Для TF оценка точная (та же формула, что у PrimeNet).
- Для PRP и P-1 точной формулы у PrimeNet нет публичной. Поэтому до первого засчитанного результата пишется «н/д», дальше оценка строится по фактическому кредиту прошлого теста с поправкой на размер экспоненты (≈).

## Оптимизация под RTX 30/40/50

- **mfaktc:** `GPUSieveSize=2047` (замер на RTX 5060 Ti: +2,2 %), `GPUSieveProcessSize=16` (32 медленнее на 1 %), построчный лог. Скорость mfaktc на всех трёх поколениях упирается в целочисленное умножение, поэтому настройки одинаковые.
- **PRPLL, тюнинг:** при первом запуске на новой модели GPU выполняется `prpll -tune inplace,exp=<диапазон>`. Диапазон узкий — экспонента задания ±3 %, кратно 5M (для first-time PRP обычно ~150M–165M): тюнятся 1–2 размера FFT, поэтому это занимает 5–15 минут, а не час. Жёсткий предел — 20 минут (`PRPLL_TUNE_MAX_MIN`); не уложился — работа идёт с настройками PRPLL по умолчанию. Если в кэше уже есть тюнинг этой модели на более широкий диапазон, покрывающий нужный, он используется без повторного тюнинга. **RTX 30 и старше (compute capability < 8.9) не тюнятся** — выигрыш на них мал. Результат хранится в `/data/tune-cache/<модель>-<бэкенд>-<версия PRPLL>-<диапазон>/` и попадает во внешний бэкап. Ход виден в `gimps-watch` (строки `[GPUn TUNE]` раз в 5 минут). Отключить: `PRPLL_TUNE=0`, принудительно тюнить (в т.ч. RTX 30): `PRPLL_TUNE=1`.
- **PRPLL, кэш ядер** (`-cache`, по умолчанию): скомпилированные под GPU ядра сохраняются в `kernel-cache/`, перезапуск PRPLL не тратит минуту на компиляцию.
- **Несколько тестов на одной GPU:** `PRPLL_WORKERS=2` запускает два PRP-теста параллельно (PRPLL `-workers 2`, AutoPrimeNet `--num-workers 2`). На больших картах (4090/5090) это иногда даёт +5–15 % суммарной скорости, но не всегда — сравните суммарные «мкс/ит» в `gimps-watch` до и после.
- **CPU-задачи** (mprime) идут с приоритетом `nice 19`, и одно ядро оставлено GPU-программам. Скорость GPU не падает.

## Надёжность: самотест, сторож, уведомления

- **Самотест GPU перед работой** (`GPU_SELFTEST=1`, раз в сутки на машину): PRPLL проверяет известное простое M1257787 в отдельной папке (результат никуда не отправляется). Не прошёл — воркер этой GPU выключается (файл `/data/.disabled-prp-gpuN`) и приходит уведомление: такую машину лучше сменить. mfaktc свой короткий самотест делает сам при каждом старте.
- **Ошибки Gerbicz (EE):** больше `EE_MAX_PER_HOUR` (3) за час — PRP-воркер выключается, чтобы неисправная карта не портила результаты и вашу репутацию в PrimeNet.
- **Сторож:** если воркер ничего не пишет дольше `WATCHDOG_MIN` (20 мин) — ни в свой вывод, ни в собственный лог PRPLL (`gpuowl-*.log`), — он перезапускается; больше 3 зависаний за 3 часа — выключается. Вывод PRPLL и mfaktc построчный (`stdbuf -oL`), поэтому проценты в журнале идут ровно, без пачек.
- **Переменные On-start в SSH-сессии:** `gimps-start` сохраняет их (логин, ключи R2, уведомления) в `/data/.onstart.env` (права 600, в бэкап не попадает), поэтому `gimps-backup`, `gimps-stop` и перезапуск `gimps-start` из SSH работают с теми же настройками.
- **SSH на «капризных» хостах:** если vast.ai кладёт `authorized_keys` с неверными правами (в логе `bad ownership or modes`), `gimps-start` чинит права и выключает `StrictModes` до старта sshd.
- **Падения при старте:** 5 падений подряд в первые 5 минут работы (сломанный драйвер, CUDA) — воркер выключается.
- Выключенный воркер видно в `gimps-watch`/`gimps-status`; вернуть: `rm /data/.disabled-<имя>` — он запустится сам в течение минуты.
- **Уведомления** (по желанию) — в Telegram и/или на любой вебхук (например, [ntfy.sh](https://ntfy.sh) — приложение на телефон без регистрации):
  ```bash
  export NOTIFY_TELEGRAM_TOKEN=<токен бота от @BotFather>
  export NOTIFY_TELEGRAM_CHAT=<ваш chat_id, его покажет @userinfobot>
  export NOTIFY_WEBHOOK_URL=https://ntfy.sh/<придумайте-длинное-имя-топика>
  export NOTIFY_LEVEL=important     # all — ещё и о каждой завершённой задаче и засчитанном кредите
  ```
  Приходят: найден делитель, вероятно простое, выключение воркера, зависание, ошибки бэкапа (не чаще раза в час), запуск/остановка расчёта. Проверить: `gimps-notify "тест"`.
- **Логи** обрезаются автоматически: файл больше `LOG_MAX_MB` (20 МБ) сокращается до последних 5 МБ. Логи воркеров (`gpuowl-*.log`, `autoprimenet.log`) в бэкап не попадают.

## CPU: mprime параллельно с GPU

Включено по умолчанию (`CPU_WORK=auto`). При первом старте `gimps-cpu-setup` сам настраивает mprime под ваш логин:
- компьютер `<GIMPS_NAME>-cpu`;
- тип работы `CPU_WORKPREF` (по умолчанию **4 = P-1**: задания на часы, удобно для аренды);
- ядер — сколько выделено контейнеру, минус одно;
- память для P-1 stage 2 — половина лимита контейнера (макс. 64 ГиБ).

После этого mprime работает в фоне.

- Проверить: `gimps-watch CPU`, `gimps-status`, папка `/data/cpu/`.
- Отключить: `CPU_WORK=0`.
- Другая работа: `CPU_WORKPREF=150` (PRP, дни–недели на CPU), `5` (ECM).
- Если автонастройка не прошла (это видно в `gimps-start.log` и `/data/cpu/setup.log`), настройте вручную: `cd /data/cpu && ./mprime -m`, затем перезапустите `gimps-start`.
- Перед удалением машины незавершённое CPU-задание верните: `cd /data/cpu && ./mprime -m` → *Advanced → Unreserve exponent*.

## 0. Что считать: PRP или TF

**PRP (`GIMPS_MODE=prp`, по умолчанию)** — это и есть поиск нового простого Мерсенна. С появлением PRPLL-NTT (целочисленные и FP32-гибридные преобразования) потребительские RTX считают PRP быстро, и слабый FP64 больше не мешает. Бенчмарки авторов (сборка 2026-10-09, экспонента 136 279 841):

| GPU | мкс/итерация | ≈ часов на один тест ~140M |
|---|---|---|
| RTX PRO 6000 Blackwell | 125 | ~4,9 |
| RTX 5090 | 135 | ~5,3 |
| H100 (сборка августа) | 182 | ~7,1 |
| A100 (сборка августа) | 332 | ~12,9 |
| RTX 4070 Ti Super | 325 | ~12,6 |
| RTX 4060 | 1071 | ~42 |

**Стоимость одного теста** = `мкс/ит × экспонента / 3,6·10⁹ × $/час`.
Пример: 5090 за $0,40/ч → 135 × 140M / 3,6e9 ≈ 5,25 ч → **≈ $2,1 за тест**.
Реальную скорость PRPLL пишет в лог (`us/it`). Сверьте её с ценой за первые 10 минут и сравнивайте варианты по этой формуле.

**TF (`GIMPS_MODE=tf`)** — поиск делителей (mfaktc). Простое так не найти, но для проекта это полезная работа, и быстрее всего она идёт на картах с сильным INT32. Задания короткие (минуты–часы), поэтому TF удобен для коротких или прерываемых (interruptible) аренд.

## 1. Подготовка (один раз): собрать образ через GitHub

Docker на телефоне или ноутбуке не нужен: образ собирает GitHub Actions бесплатно.

1. Создайте на GitHub **новый репозиторий** (например `gimps-gpu`, можно Private).
2. Загрузите туда **всё содержимое архива** (при обновлении — с заменой; файлы, появившиеся в последних версиях: `gimps-monitor`, `gimps-watch`, `gimps-cpu-setup`, `mprime-setup.exp`, `gimps-notify`, `test-monitor.sh`), включая скрытую папку `.github/` (Add file → Upload files, или `git push`).
   Ветка должна называться `main`.
3. Откройте вкладку **Actions**. Workflow `build-image` запустится сам и будет работать ~15–25 мин. Дождитесь зелёной галочки.
4. Сделайте образ публичным, чтобы облако скачивало его без логина. Профиль → **Packages** → `gimps-gpu` → Package settings → *Change visibility* → **Public**.
   В образе нет никаких секретов: логин передаётся переменной при запуске.
   Если образ нужен приватным, впишите в шаблон vast.ai логин GitHub и токен с правом `read:packages`.

Ваш образ: **`ghcr.io/<ваш-логин-github-маленькими-буквами>/gimps-gpu:latest`**

> Обновить PRPLL до свежего master: Actions → build-image → *Run workflow* → `prpll_ref = master`.

## 2. Вариант A — vast.ai с готовым образом (рекомендуется)

**Создать шаблон** (Templates → New), один раз:

| Поле | Значение |
|---|---|
| Image | `ghcr.io/<логин>/gimps-gpu`, тег `latest` — или, надёжнее, неизменяемый `sha-<7 символов коммита>` (Packages → gimps-gpu): машина возьмёт именно проверенную сборку |
| Launch mode | **SSH** (так можно зайти и посмотреть статус) |
| Docker options | `-e GIMPS_USER=<логин mersenne.org> -e GIMPS_MODE=prp` |
| On-start script | см. ниже |
| Disk | **≥ 50 ГБ** на 1 GPU (+30 ГБ на каждую следующую). Под proof-файлы нужно ~18 ГБ на тест |

On-start script:
```bash
export GIMPS_USER=<логин mersenne.org>   # дублируем на случай, если env не прокинулся
export GIMPS_MODE=prp                    # или tf
gimps-start --daemon
```

**Арендовать:** выберите оффер с фильтром *CUDA ≥ 12.9* и этим шаблоном. Примерно через 1–2 минуты после старта:
```bash
ssh -p <порт> root@<ip>      # команда есть в карточке инстанса (кнопка >_)
gimps-status
```

> В SSH-режиме vast.ai не выполняет ENTRYPOINT образа, поэтому запуск идёт через On-start.
> В режиме *Entrypoint* можно оставить поле On-start пустым: образ сам вызовет `gimps-start`.

## 3. Вариант B — без своего образа (bootstrap)

Подходит, если не хочется возиться с GitHub, или нужна разовая проба.

1. Арендуйте инстанс с образом **`nvidia/cuda:12.9.1-devel-ubuntu24.04`** (SSH-режим, диск ≥ 50 ГБ).
2. Скопируйте `bootstrap.sh` на машину. Либо `scp -P <порт> bootstrap.sh root@<ip>:`, либо откройте файл, скопируйте текст и вставьте в `nano bootstrap.sh`.
3. На машине:
```bash
bash bootstrap.sh                                # сборка 3–6 минут
GIMPS_USER=<логин> GIMPS_MODE=prp gimps-start --daemon
gimps-watch
```
После пересоздания инстанса сборку придётся повторить. При остановке и запуске того же инстанса всё сохраняется.

## 4. Вариант C — обычная облачная VM (любой провайдер)

На VM нужны драйвер NVIDIA ≥ 575, Docker и NVIDIA Container Toolkit. В GPU-образах облаков (Deep Learning VM и т.п.) они обычно уже стоят.
```bash
docker run -d --name gimps --gpus all --restart unless-stopped \
  -v gimps-data:/data \
  -e GIMPS_USER=<логин> -e GIMPS_MODE=prp \
  ghcr.io/<логин-github>/gimps-gpu:latest

docker exec gimps gimps-status       # статус
docker logs -f gimps                 # общий лог
docker stop -t 120 gimps             # корректная остановка (чекпойнт)
```

## 5. Как понять, что всё работает

- `gimps-watch` — живой журнал: новая задача с оценкой и снимком GPU, затем строка на каждый 1 %.
- `gimps-status` показывает загрузку GPU (должна быть ~100%), задание в `worktodo` (строка `PRP=...`) и последние строки лога PRPLL с `us/it` и ETA.
- Через ~1 час машина появится на https://www.mersenne.org/cpus/ под именем `cloud-prp0` (`cloud-prp1`… для других GPU).
- Логи лежат в `/data/logs/`: `prp-gpu0.log` (PRPLL), `apn-gpu0.log` (AutoPrimeNet), `gimps-start.log`.
- Все рабочие файлы и чекпойнты хранятся в `/data/prp-gpu<N>/`.

## 6. Завершение аренды — важно

Каждое задание закреплено за вами. Брошенное задание висит, пока не истечёт срок, и тормозит проект. Порядок такой:

| Ситуация | Команда |
|---|---|
| Хочу закончить аренду, но досчитать начатое | `gimps-stop --finish`. Новые задания больше не берутся (запрет сохраняется при перезапуске этой машины; если слот потом продолжит другая машина — снимается сам; вручную — `GIMPS_NO_NEW_WORK=0`). Когда `gimps-status` покажет пустой worktodo, выполните `gimps-stop` и удалите инстанс |
| Нужно остановить прямо сейчас, потом продолжу на этой же машине | `gimps-stop`, затем **Stop** инстанса (диск сохраняется). Следующий старт продолжит с чекпойнта |
| Машина умерла / не поднимается | Если включён внешний бэкап (6a), запустите новую с теми же `BACKUP_*`, и она продолжит сама |
| Ухожу совсем, досчитывать не буду | `gimps-stop --unreserve`. Задания GPU вернутся в PrimeNet, а их чекпойнты удалятся из слота бэкапа (чтобы другая машина не продолжила уже чужие задания). После этого можно **Destroy** |

`gimps-stop` дожидается сохранения чекпойнтов и **досылает результаты и PRP-proof**.
Не удаляйте машину, пока он не напишет «Готово»: без загруженного proof тест потом придётся целиком перепроверять (double-check).

Перенос на другую машину вручную: скопируйте папку `/data` целиком (`scp -r` или *Copy* в vast.ai) и запустите там `gimps-start`. Автоматический вариант описан в разделе 6a.

## 6a. Внешний бэкап чекпойнтов: продолжить на другой машине, если эта не поднимется

Если задать хранилище, всё состояние из `/data` (чекпойнты PRPLL, накопленные proof-остатки, задания, `prime.ini` с идентификатором машины в PrimeNet) копируется в ваш **Google Drive** (или в S3-хранилище):

- **каждые 30 минут** (`BACKUP_INTERVAL_MIN`), для всех видов расчётов: PRP и TF на GPU, P-1 на CPU (mprime), кэш тюнинга PRPLL. Загружаются только новые файлы, поэтому потеря при внезапной смерти машины — не больше 30 минут счёта;
- **при остановке через `gimps-stop`** (и `docker stop` в режиме ENTRYPOINT, если хватает времени до SIGKILL) — сразу после сохранения чекпойнта. В SSH-режиме vast при Stop/Outbid сигнал до `gimps-start` обычно не доходит, поэтому при внезапном переезде теряется до `BACKUP_INTERVAL_MIN` минут счёта.

Каждый бэкап сначала делает мгновенный снимок `/data` на жёстких ссылках (место не занимает) и загружает его: файлы, которые программы перезаписывают во время загрузки, больше не ломают синхронизацию, а каждому сейвфайлу в бэкапе гарантированно соответствуют все proof-остатки до его итерации.

**На новой машине ничего делать не нужно.** Запустите её с теми же переменными `BACKUP_*`. `gimps-start` увидит пустой `/data` и выберет слот в хранилище (см. ниже); если там брошенная машина — скачает её состояние, и PRPLL/mfaktc/mprime продолжат с последних чекпойнтов под тем же «компьютером» в PrimeNet. GPU может быть другой модели, но **их должно быть столько же** и `GIMPS_MODE` должен совпадать (папки `prp-gpu0`, `prp-gpu1`… привязаны к номерам GPU).

**Слоты: можно запускать сколько угодно машин с одним шаблоном.** В хранилище есть слоты `BACKUP_NAME`, `BACKUP_NAME-2` … `-9`. Работающая машина пишет в свой слот «пульс» каждые 2 минуты (возраст пульса считается по часам хранилища, а не машин). Новая пустая машина:
1. если есть **брошенный** слот (данные есть, пульса нет дольше 6 мин) — забирает его и продолжает задания той машины;
2. иначе — занимает первый **пустой** слот и стартует с нуля;
3. **живые** слоты не трогает никогда.

**Хранилище недоступно — с нуля не стартуем.** Если R2 не отвечает или ключи/бакет неверны, `gimps-start` не начнёт «чистый» запуск (это бросило бы задания и затёрло бы бэкап): повторяет попытку каждую минуту до `BACKUP_RESTORE_WAIT_MIN` (30 мин), пишет причину в `gimps-watch`, потом останавливается.

**Защита бэкапа:**
- в слот, где пишет другая живая машина, синхронизация не идёт;
- если в хранилище есть папка воркера (`prime.ini`), а локально её нет, синхронизация отказывается её удалять (`BACKUP_ALLOW_SHRINK=1` — если удаление задумано);
- за раз удаляется не больше `BACKUP_MAX_DELETE` (300) файлов;
- два бэкапа одновременно не идут (блокировка), а второй `gimps-start` на той же машине не запустится.

### Cloudflare R2 (рекомендуется)

1. В Cloudflare: **R2 → Create bucket**, например `gimps-backup`.
2. **R2 → Manage R2 API Tokens → Create API Token**: права *Object Read & Write*, только этот бакет. Сохраните **Access Key ID** и **Secret Access Key**.
3. **Account ID** — справа на главной странице R2.
4. Добавьте в **On-start script** приватного шаблона vast.ai (ключи — только туда, не в GitHub и не в чат):
```bash
export BACKUP_BUCKET=gimps-backup
export BACKUP_R2_ACCOUNT_ID=<Account ID>
export BACKUP_S3_ACCESS_KEY=<Access Key ID>
export BACKUP_S3_SECRET_KEY=<Secret Access Key>
export BACKUP_NAME=vast            # базовое имя слотов: vast, vast-2 … vast-9 выбираются автоматически
gimps-start --daemon
```
5. После старта выполните на машине `gimps-backup check`: должно появиться «доступ ... есть».

Адрес (`https://<Account ID>.r2.cloudflarestorage.com`) и регион `auto` подставляются сами. Бесплатно в R2 дают 10 ГБ хранения, а входящий и исходящий трафик бесплатны. При proof power 6 одна GPU с PRP занимает около 1,2 ГБ.

### Настройка Google Drive (один раз, ~15 минут)

Google требует собственный OAuth-клиент: общий клиент rclone в 2026 году отключается. Это бесплатно.

**Шаг 1. OAuth-клиент в Google Cloud** (https://console.cloud.google.com, тот же Google-аккаунт)
1. Создайте проект, например `gimps-backup`.
2. *APIs & Services → Enable APIs and services* → найдите **Google Drive API** → **Enable**.
3. *Google Auth Platform* (OAuth consent screen): имя приложения `rclone`, ваш email, Audience: **External**, контакт → **Create**.
4. *Data Access → Add or remove scopes* → отметьте `.../auth/drive.file` → **Save**.
5. *Audience* → **Publish app** → Confirm. Если не опубликовать, токен будет истекать каждые 7 дней.
6. *Clients* → **Create client** → тип **Desktop app** → **Create**. Сохраните **Client ID** и **Client secret**.

**Шаг 2. Получить токен** (на своём компьютере)
1. Скачайте rclone для Windows: https://rclone.org/downloads/ (zip), распакуйте, откройте PowerShell в этой папке.
2. Запустите `.\rclone.exe config` и ответьте:
   - `n` (new remote), имя `gd`, тип `drive`;
   - `client_id` и `client_secret` — из шага 1;
   - scope: **`drive.file`** (rclone увидит только свои файлы, а не весь ваш Диск);
   - остальное Enter по умолчанию; `Use web browser to automatically authenticate?` → `y`.
   - Откроется браузер, войдите в Google. Появится предупреждение «приложение не проверено» — это ваше же приложение: *Advanced → Go to rclone* → **Allow**.
   - `Configure this as a Shared Drive?` → `n`, затем `y` (сохранить) и `q`.
3. Выполните `.\rclone.exe config show gd` и скопируйте строку `token = {...}`. Нужна JSON-часть целиком, от `{` до `}`.

**Шаг 3. Передать токен и клиент машине.** Добавьте в On-start script шаблона vast.ai (шаблон держите приватным: токен даёт доступ к файлам бэкапа):
```bash
export BACKUP_GDRIVE_CLIENT_ID='<Client ID из шага 1>'
export BACKUP_GDRIVE_CLIENT_SECRET='<Client secret из шага 1>'
export BACKUP_GDRIVE_TOKEN='{"access_token":"...","token_type":"Bearer","refresh_token":"...","expiry":"..."}'
export BACKUP_NAME=vast-1          # подпапка этой «машины» в папке gimps-backup на Диске
gimps-start --daemon
```
Токен вечный (обновляется сам), пока вы не отзовёте доступ в настройках Google-аккаунта.

**Место на Диске.** Бесплатно дают 15 ГБ, и они общие с Gmail. На одну GPU нужно примерно:

| Настройка | Объём бэкапа | После переезда |
|---|---|---|
| по умолчанию (proof power ~10) | ~18 ГБ | тест закончится с proof |
| `-proof 8` | ~4,5 ГБ | тест закончится с proof |
| **`PRP_PROOF_POWER=6` (по умолчанию)** | **~1,2 ГБ** | тест закончится с proof |
| `BACKUP_PROOF=0` | ~70 МБ | тест продолжится, но, скорее всего, без proof: результат засчитают, а проверять его будут повторным полным тестом |

**Почему не GitHub.** Git хранит каждую версию файла навсегда. Чекпойнт весит ~17 МБ и меняется каждые 10 минут, так что репозиторий будет расти на гигабайты в сутки. GitHub такие репозитории ограничивает (файлы >100 МБ отклоняются, рекомендуемый размер репозитория до 1 ГБ), а его правила запрещают использовать репозиторий как файловый бэкап.

**Альтернатива без OAuth — S3-хранилище** (Cloudflare R2 или Backblaze B2, у обоих 10 ГБ бесплатно): ключ доступа создаётся в два клика.
```bash
export BACKUP_BUCKET=<бакет>  BACKUP_S3_ENDPOINT=<endpoint>  BACKUP_S3_REGION=<регион; для R2: auto>
export BACKUP_S3_ACCESS_KEY=<ключ>  BACKUP_S3_SECRET_KEY=<секрет>  BACKUP_NAME=vast-1
```

### Команды

| Команда | Что делает |
|---|---|
| `gimps-backup check` | проверить доступ к хранилищу (сделайте один раз после запуска) |
| `gimps-backup` | синхронизировать прямо сейчас |
| `gimps-backup ls` | все занятые слоты: состояние (live / stale / mine), пульс, объём |
| `gimps-backup restore` | восстановить свой слот вручную (на пустой машине `gimps-start` делает `gimps-backup claim` сам) |
| `FORCE=1 gimps-backup restore` | восстановить, не дожидаясь устаревания пульса. Только если старая машина точно мертва |

В `gimps-status` видно время последнего успешного бэкапа. Подробный лог — `/data/logs/backup.log`.

**Объём** — см. таблицу выше. После загрузки proof в PrimeNet остатки удаляются и из хранилища.
На vast.ai исходящий трафик машины оплачивается по тарифу хоста (цена за ГБ видна при наведении на цену оффера). Это объём бэкапа на каждый тест.

Их можно задать через `-e` или записать в файл `/data/gimps.env`.

|---|---|---|
| `GIMPS_USER` | `ANONYMOUS` | Логин mersenne.org. **Обязательно укажите свой** |
| `GIMPS_MODE` | `prp` | `prp` (PRPLL) или `tf` (mfaktc) |
| `GIMPS_WORKPREF` | 150 / 12 | Тип работы PrimeNet: 150 first-time PRP, 151 double-check PRP, 152 world-record PRP, 153 100M-digit, 155 DC с proof; 12 TF |
| `GIMPS_GPUS` | все | Какие GPU использовать, напр. `0,1` |

| `PRPLL_CACHE` | `1` | Кэш скомпилированных ядер PRPLL (`-cache`) |
| `GPU_SELFTEST` | `1` | Самотест GPU перед работой (раз в сутки) |

## 8. Если что-то не так

- **`nvidia-smi не видит GPU`.** Контейнер запущен без GPU (`--gpus all`), или драйвер хоста слишком старый. На vast.ai выбирайте оффер с CUDA ≥ 12.9.
- **В `prp-gpu0.log` ошибки CUDA/NVRTC.** Задайте `PRPLL_BACKEND=opencl` и перезапустите (`gimps-stop`, затем `gimps-start --daemon`). Проверить OpenCL можно командой `clinfo -l`.
- **`No work to do`** в первые минуты — норма: AutoPrimeNet ещё регистрируется. Если сообщение не пропадает, смотрите `apn-gpu0.log`: там будет ошибка логина или сети.
- **Мало места на диске.** Proof-файлы большие. По умолчанию уже стоит минимальный разумный `PRP_PROOF_POWER=6` (~1,1 ГБ на тест).
- **Подробные логи:** `tail -f /data/logs/prp-gpu0.log`. Собственный лог PRPLL — `/data/prp-gpu0/gpuowl-0.log`.
